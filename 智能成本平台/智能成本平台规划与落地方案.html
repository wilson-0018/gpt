1.1

平台定位与建设目标

成本数据从哪里来

汇集报价、成交、材料行情、研发规格与历史配置，说明来源、条件和时间。

每颗料的成本可解释

按材料、二级料、用量、工艺和费用拆解，说明模型如何建、结果怎么算。

成本应用可以闭环

测算用于报价核价，结果进入项目和采购决策，后续跟踪目标与降本。

平台目标：把有来源的成本数据沉淀为可解释的物料成本模型，用于报价、整机竞争力判断和量产降本管理。

平台重点回答四个业务问题

业务重点平台要给出的答案
① 合理成本怎么算，模型怎么建？按品类建立材料、二级料和工艺模型，给出单颗物料成本、关键参数及偏差原因。
② 内部如何对比和判断报价？采购内部对供应商不同轮次报价、历史可比价和模型测算价进行对比，定位不合理项，支撑核价与议价。
③ 新品/芯片BOM和整机成本是否可控、有竞争力？对接BOM核价工具，拆出器件贡献、整机成本和阶段变化，判断目标是否超出、配置和价格是否有优化空间。
④ 量产物料的成本目标和降本计划如何推进？分解料号目标，识别材料传导与价格差距，形成负责人、动作、期限和结果跟踪。

二、核心功能域架构

2.1

业务能力与核心功能域架构

业务能力定义“做什么”；成本核价模型定义“怎么算”；数据实体保存输入与结果；技术栈负责取数、计算、展示和系统协同。六项核心功能共用价源、物料结构和模型，不为每个应用另建价表。

2.2

技术架构：前台、中台与后台

层级关键实现
前台Vue 3管理表单与复杂表格，TypeScript定义业务数据结构，Vite构建；组件库与图表库由IT选型，支持成本树、行级错误和预警详情。
中台Spring Boot 3组织领域服务、事务与REST接口；公式引擎用受限表达式和十进制金额；AI只通过授权工具查数与调用公式，不直接写生效数据。
后台MySQL保存关系数据；附件按权限存储；后台任务负责同步、导入与重算。采购运营/IT维护访问、接口异常、备份及运行问题。

3.1　成本核价模型

｜ 一期

将规格、材料和工艺转为可计算的物料模型，解释每颗料的成本构成。

品类成本核价模型中心

一级模组成本由自身成本要素与展开二级料构成。先复用结构件样板，再按屏、摄像头、电池、PCB、指纹配置独立参数；数据不足的芯片采用可解释的市场/历史对标，不能假装掌握完整制造成本。

优先品类核心成本因子关键模型参数业务用途
PCB / HDI铜箔、PP、板材/芯板、钻孔、电镀、压合、测试层数、阶数、孔密度、拼板利用率、线宽线距、良率识别材料传导、复杂工艺加价和报价偏差。
显示屏面板、触控、盖板、驱动IC、FPC、贴合、背光/封装尺寸、分辨率、刷新率、亮度、材料类型、贴合良率比较方案与同档配置，拆分模组合理成本。
摄像头模组Sensor、Lens、VCM、FPC、AA组装、测试像素、Sensor尺寸、镜片数、防抖、封装与良率穿透关键二级料，判断模组报价。
电池及充电电芯材料、保护板、PACK、主控IC、MOS、磁性件、认证容量、电压、单双电芯、快充功率、工艺和良率容量/快充规格取舍，原料变化传导。
指纹指纹芯片、结构/盖板、组装与测试识别方案、芯片型号、封装与组装良率芯片采购价与模组加工模型组合核价。
结构件金属/塑胶/玻璃、CNC、注塑、喷涂、阳极、模具重量、工序、表面处理、良率、模具摊销沿用样板统一要素和参数配置。
存储 / 芯片（后续）晶圆、封装测试、容量、协议、供需与原厂策略容量、制程、代际、封装、周期和汇率制造数据不足时采用行情/历史对标，注明方法边界。
输入 / 输出内容
输入项目/器件清单、品类和技术规格，材料/辅材/二级料净用量与工艺路线；成本库生效材料价、原厂价、历史报价及供应商费用配置。每项输入保留单位、币税、日期和来源；区分设计净用量、已含损耗用量及良率。模型Owner明确利用率、工时、折旧与利润定义。
输出可复用的成本核价模型、器件成本卡及成本区间；成本卡展开材料、二级料、加工、折旧、人工和其他费用，并展示公式、取价依据与关键假设。同步输出高敏感参数和缺项清单，供RFI定商、量产重算和二期整机成本使用。
处理过程业务与计算逻辑
匹配与展开按品类、材料和关键规格匹配模板，展开一级成本树。已按子件展开的模组不再计入整包单价；指定原厂二级料价与模型估算分开标识。资源商务/采购确认模型适用范围。
计算与核校材料成本=净用量×单价÷利用率；工序成本按工时/节拍、费率和适用良率计算。若用量已含损耗或加工费已含人工、折旧，不重复加计；缺关键价格或参数时返回待补，不按零汇总。
区间与发布对已确认的参数上下界形成情景，标识其假设，不冒称统计置信区间。以独立验证样本核对测算偏差，解释大偏差；确认后的模型和成本卡才供业务引用，变更保留原输入。

外部协同：资源商务/采购提供参数、样本和价源；供应商报价及原厂价通过SRM/文件接入。主数据与费用定义由对应Owner确认。

3.2　RFI定商应用

｜ 一期

以目标成本为对比基准，接收SRM多轮报价，结构化比价并给出AI辅助RFI定商建议；采购最终确认供应商、份额与价格，形成项目定商数据及份额统计。

输入 / 输出内容
输入项目、器件规格、采购量、成本核价模型和经确认的RFI目标/比较基准；供应商多轮报价、工艺参数、资格与份额规则。保留MOQ、币税单位、账期、交期和有效期；二期可引用业财维护的适用规格目标。
输出结构化报价对比、对目标与模型的差距、澄清项及AI定商建议；采购确认的供应商、份额、最终价与理由。保留建议和最终结果对照，沉淀项目、供应商、成交价、份额和来源RFI轮次。
处理过程业务与计算逻辑
标准化与映射SRM发起RFI并接收供应商多轮报价；平台提取报价项，统一规格、用量、币税和商务条件，映射成本要素。未识别、漏报或不可比的项目列入待核验。
差距与解释分别对比RFI目标成本、模型与可比历史价；GAP基准明确，零/缺基准不计算。AI结合报价、目标、工艺参数和批准规则生成建议及证据，不替代资格判断和采购选择。
确认与沉淀采购确认供应商、份额与最终价格，按授权走SRM定商。调整建议或重新报价进入下一轮，保留历史；定商结果回流后汇总项目与供应商份额，记录偏离建议的原因。

业务系统配合：SRM保留发起RFI、供应商多轮报价与正式定商；需对接报价单和结果数据，二期增加按规格目标带出。平台新增结构化提取、目标对比、AI建议和定商数据/份额统计。

3.3　量产调价管理

｜ 一期

材料或二级料行情变化后重算器件成本，形成溢价清单和议价包，经人审后推进调价。

输入 / 输出内容
输入原料/二级料降价事件、幅度与生效时间，成本库行情/趋势更新；器件—二级料对应关系、用量、利用率、工艺模型和供应商现行净价/成交价。补充合同传导比例、调价周期、滞后窗口、已执行降价及规格/汇率变化，明确受影响采购范围。
输出受影响器件与供应商清单、理论Should-cost变化、当前采购价与新模型的差距、可解释的溢价区间；议价建议草稿、人工确认记录和议价包。谈判结果回流后归档新价及依据，区分预计机会、已签价格和按实际量核对的降本结果。
处理过程业务与计算逻辑
定位与重算先将行情更新为可用输入，再沿二级料关联定位器件和供应商。保留变动前后条件，在其他假设不变时重算Should-cost；已含在模组或工艺费用中的成本不重复传导。
对比与出清单对比现行净价/成交价与新成本，扣除已传导降价，核查合同滞后、规格升级、汇率等合理差异，形成候选溢价。无充分数据时标为待核实，不能把全部差额视为可谈收益。
草稿、人审与归档可选Agent整理谈价证据和追问，提交资源商务/采购人审；退回后修改参数或建议，通过才输出议价包。按实际谈判、SRM生效结果更新任务，新价与记录回到成本库，未达成须记录原因。

业务系统配合：SRM执行询议价、RFQ调价和价格生效，返回最终新价；现有价源提供成交与实际量。平台生成依据与任务，不自动对供应商发价。

3.4　新品AI拆解

｜ 二期

解析研发需求规格和图纸，复用历史成本配置，快速生成成本模型初版。

输入 / 输出内容
输入用户上传或IPM提供的版本化需求规格、关键参数、结构/工艺图纸和构成说明；历史品类模型、费用配置、材料/二级料字典和已确认成本参数。先限定清晰资料格式，标记图纸密级、适用机型、关键尺寸/材料及设计约束。
输出可编辑的成本模型初版，含成本要素、公式模板、参数初值与历史引用；参数提取位置、相似案例及差异依据，另列缺项和假设。经资源商务/采购确认后发布为模型版本，用于正式核价；AI初版不直接成为定商价或正式研发BOM。
处理过程业务与计算逻辑
提取与匹配识别材料、尺寸、容量、工艺等品类参数，保留原文位置和待确认项。先按品类、工艺、关键规格筛选历史模板，再用AI推荐相似配置；明确哪些参数可沿用、哪些因新工艺需重估。
生成与试算AI将识别参数填入受控模板，通过公式服务试算成本区间。没有依据的用量、费率和价格不得猜填；缺关键项时仅生成模型结构与补数清单，不输出假精确总成本。
配置与确认NPM采购/研发澄清资料，资源商务/采购确认要素、参数与假设，修改后形成正式模型。资料换版重新生成差异，不覆盖旧任务；分别统计参数准确率、模型初版可用性和人工修正耗时。

业务系统配合：IPM提供需求规格、图纸及变更版本，只读获取；研发主数据与正式BOM仍在原系统维护。模型服务采用企业批准的AI接口。

3.5　目标价及降本管理

｜ 二期

本平台集中管理两类目标，监控报价偏差、项目整机达成及量产降本执行。

目标对象维护粒度业务引用 / 本平台监控
物料目标业财维护物料编码；电池、内存等部分到规格型号竞价/RFI按规格型号带出；量产RFQ按物料编码引用，平台监控对比与降本执行。
项目整机目标项目/机型及阶段，维护责任按NPM流程确认根据NPM BOM核价管理目标，输出整机差距和超标器件。
输入 / 输出内容
输入业财维护的物料目标：到物料编码，电池/内存等部分到规范规格型号；包括目标值、币税单位、有效期和适用范围。项目整机目标按项目/机型及阶段管理，结合NPM BOM核价。同步接收报价/订单、新价生效、计划/实际量和降本动作，用于执行监控。
输出规格级/编码级物料目标清单、项目整机目标与达成结果；RFI/RFQ引用对照、超目标差距及预警，按采购员/供应商/料号跟踪动作和期限。分别展示计划、机会、已签与实际兑现，缺目标或缺执行数据时显示待补，不误判已达成。
处理过程业务与计算逻辑
维护与关联目标业财维护物料编码级/部分规格级目标；项目整机目标按NPM管理口径确认。目标支持直接维护，降本率仅作辅助测算。编码/规格映射须人工确认；物料目标之和不自动等于整机目标。
监控引用与偏差竞价/RFI按规格型号引用，量产RFQ按物料编码引用；平台比较相同口径报价与目标，按业务阈值生成预警。项目按同阶段BOM核价对照整机目标，定位超标器件。无目标、零目标、条件不符返回待核验。
跟踪降本执行记录差距原因、责任人、动作与期限，接收SRM生效新价及实际执行量更新进度。业财核对基准和金额，排除规格/汇率影响，防止同一降价在调价、技术降本和目标任务中重复计收益。

业务系统单独改造：SRM竞价/RFI增加规格型号目标价带出与对比；RFQ增加物料编码目标价引用、对比/预警，并回传执行结果。NPM/BOM核价工具提供项目核价结果及目标对照所需字段。

3.6　整机全周期成本

｜ 二期

衔接NPM BOM核价，管理整机目标、阶段成本、横评及整机/器件成本趋势。

输入 / 输出内容
输入BOM核价工具提供项目/机型、阶段、BOM/结果版本、父子行、料号、用量、单位、行价/金额与合计；IPM提供规格和变更。读取器件成本卡、成交/报价、项目整机目标、汇率与情景窗口；横评需要同档机型配置和可比条件，竞品价格注明估算来源。
输出NPM整机核价结果、器件成本贡献及项目目标差距；概念、打样、量产各阶段成本对照，配置方案横评和待优化清单。分别展示固定BOM的器件价格趋势与实际BOM迭代的整机成本变化，并区分历史事实、模型估算和未来情景。
处理过程业务与计算逻辑
接入与对账以项目+BOM版本+源结果版本识别一次核价，核对原工具合计与明细。按父模组或展开子件选择唯一汇总路径，缺价不补零；行价口径、数量或层级不符时列出差异，不静默改原结果。
汇总与目标对比整机成本=Σ用量×可用单价+明确整机级费用。概念阶段允许确认模型/类比估算，量产以生效净价为主。按项目整机目标比较差额，资源商务确认器件价，NPM采购/研发确认阶段与配置。
横评与趋势归因同档机型先说明性能、配置及采购条件差异，再比较器件与整机成本。用固定顺序替换价格、配置等因素形成变化解释，避免把换料/用量变化说成涨价。新版本形成新结果，旧结果可追溯。

业务系统配合：BOM核价工具提供明细与结果接口，保留原工具流程；IPM提供变更。若需回传参考价，另确认字段、范围及审批，不由平台覆盖原核价结论。

3.7　技术降本（ECN/DCN）

｜ 二期扩展

用户输入变更或替代方案，AI辅助生成成本测算及净降本额度，批准后跟踪真实切换结果。

输入 / 输出内容
输入变更前后BOM、料号/规格、用量、材料和工艺差异，用户描述或IPM批准变更单；旧/新方案报价、预计实际替代量、验证/开发/模具费用、库存与在途处置。明确适用机型、BOM版本、切换时间和供应商条件，不把整个项目需求量默认当作可替代量。
输出变更前后方案成本、单位节省、预计净降本、盈亏平衡量及假设依据；AI解析结果与缺项清单、采购/研发确认记录和技术降本卡。实施后关联实际替代数量、一次性费用和新价，核对净收益，不把未认证或未切换方案计为已实现。
处理过程业务与计算逻辑
解析与比较AI提取变更点，匹配历史成本模型与价源，生成结构化方案。缺参数、缺报价或仅有文字描述时先补数；供应商新方案涉及外围器件、测试或良率变化，也一并纳入单位方案成本。
调用成本测算单位节省=原方案完整成本−新方案完整成本；预计净降本=单位节省×预计实际替代量−一次性增量费用。费用已摊入单价时不再重复扣；可退换/继续使用的库存不全额当作损失。
批准与兑现研发/质量确认替代可行性和适用范围，资源商务/采购确认价格、订单和切换条件，业财核对费用与收益。IPM保留ECN/DCN批准及工程生效；平台仅测算、跟踪，按实际替代量核对结果。

业务系统配合：IPM关联批准的ECN/DCN及适用版本；SRM处理替代料询价、价格与切换后的采购执行；验证/库存等增量费用由对应Owner确认。

3.8　阶梯价测算与监控

｜ 二期扩展

按已批准阶梯规则测算降本额度，持续核对订单应执行价并及时预警。

输入 / 输出内容
输入合同/报价中的供应商、物料、阶梯区间、各档单价、单位/币税、周期和有效期；明确单笔或累计量、按订单或收货量计量、达标后仅后续执行或追溯全量，以及分段计价。接入订单行、取消/退货/收货和实际单价，保留规则版本与源单据。
输出不同量级的阶梯成本与预计降本额度、当前命中档位和应执行价；订单执行偏差、超付风险及预警任务。阈值临近、合同到期可按需提醒；采购改价/补差后回流确认，区分预计机会、已执行价差和实际追回金额。
处理过程业务与计算逻辑
规则结构化与确认AI可辅助识别合同条款，但数量口径、周期边界、价格生效及追溯方式必须采购确认。多规则冲突、档位缺口或合同已失效时暂停自动判价，生成规则待核验项。
按情景与实绩测算规则引擎根据数量命中档位，分段计价逐段汇总；预计额度=固定基准情景金额−阶梯情景金额。预测需求与实际订单量分开，跨周期、退货和取消按批准规则回算，不用简单最低档单价套全量。
监控与处理闭环按订单事件或约定扫描周期比较执行价与应执行价。高于应执行价且超容差时预警，显示订单、档位、证据和差额；采购核实后改价或追溯补差，结果回流并关闭，不能擅自改订单价。

业务系统配合：SRM/采购订单系统提供阶梯协议与订单执行数据，承接订单改价或补差；业务确认扫描时效、容差和预警责任人。

四、实施落地

4.1

6—8个月实施里程碑

建议M1—M4完成一期三项核心能力，M5—M6试点二期三项核心能力，M7—M8稳定推广并择优实施扩展。扩展不作为六项核心功能的替代，也不要求所有品类同步达到相同深度。

月份 / 阶段具体交付业务验收
M1｜一期准备确认两类深度试点、模型Owner、价源字典、人工核价样例和报价/调价流程。输入字段、单位、费用边界及样本由资源商务/采购签认；接口Owner提供样例。
M2｜一期模型成本库、二级料映射、公式参数、成本测算及器件成本卡。人工标准样例逐行对齐；能发现缺价、单位问题和费用重复。
M3｜一期应用多家多轮报价对标、成本基线；行情重算、溢价清单和议价包。真实核价可用；量产事件有计算依据、人审和采购动作。
M4｜一期验收打通SRM引用与结果回流，验证三项一期能力；锁定二期数据与改造范围。核价结论被采用，量产议价有结果；新价与证据可归档。
M5—M6｜二期核心新品AI初版模型、两类目标管理、NPM整机与器件成本趋势；SRM目标带出改造联调。分别完成新品资料、规格/编码目标引用、项目整机目标对照的真实案例。
M7—M8｜推广与扩展完善执行监控、扩品类和运营移交；技术降本/阶梯价按价值择优试点。连续运行问题可处理；模型适用范围清楚，目标与结果分开统计，扩展有独立验收。
